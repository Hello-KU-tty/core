# Discovery prompt v1.3.5: useful result before technology observation

The PREVIEW phase replaces one existing rule with a pre-submit check for an accessible input or situation, the user's action, and a useful output or reason to return. A direction whose only completion is observing or learning the target technology must be reframed as a usable project or replaced before submitting exactly ten previews. The concrete implementation point and product effect of the learning goal, diverse directions, optional Personal Need, staged identity, and strict Core contract remain unchanged.

The synthetic, personal-data-free `discovery-v1.3.5-full-preview-value.json` fixture preserves all six authored fields of each of the ten previews durably saved by the preceding native v1.3.4 D run. It adds review questions covering technology-observation candidates, useful photo/document workflows where caching can preserve the visible feature, and directions whose user task or adoption path needs scrutiny. A separate goal-only runtime-validation contrast presents a usable configuration check and a technology demonstration with the same valid Preview shape. Human reviewers should judge reachable user input, action, result, technology necessity, first-MVP burden, and genuine diversity from the full fields; title or topic keywords are not an automated quality gate.

On Node.js 24.19.0 / pnpm 11.12.0, `pnpm test:eval` passed 32/32 and `pnpm typecheck` passed. Biome format/lint on changed source and fixture, plus `git diff --check`, passed. The evaluation verifies fixture schema, ten saved Preview positions, all six fields, review coverage, version wiring, and reconstruction of the historical v1.3.4 PREVIEW-section SHA-256 after reversing this single rule. The v1.3.4 fixture and its historical result were not relabeled.

These automated checks do **not** show that a native v1.3.5 model produces better candidates. The subsequent first native observation is recorded below. D v1.3.4 remains only a small, uncontrolled baseline; a second unseen goal and a separately controlled model comparison would be needed for a general quality claim.
