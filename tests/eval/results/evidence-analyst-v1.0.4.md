# Evidence Analyst v1.0.4 request versus user claim regression

In the isolated Kiro IDE experiment, a synthetic evaluator-authored Helper question asked the Agent to compare two date policies and separate implementation facts from unverified possibilities. The native Analyst submitted `JUSTIFIED_DECISION / STRONG / INDEPENDENT / DEMONSTRATED` for a quote that only asked the Agent to make that distinction. Its rationale inferred critical thinking from the request rather than identifying a user-authored conclusion, reason, or performed comparison. Core accepted the structurally valid, USER-sourced Proposal; this is a semantic false positive, not a learner achievement. Read-only storage inspection confirmed the later F Discovery personalization trace used this false Evidence as `basis[0].evidenceIds[0]`. That proves contamination of its input basis, not that a specific F output sentence changed because of it. The previously accepted Evidence remains stored; this prompt change does not rewrite that history.

The canonical prompt now requires an actual user-authored proposition, prediction, reasoned selection, or application for state-supporting Evidence. A request for the Agent to do the analysis, however careful, cannot become a justified decision. The rule preserves questions that contain an independently stated, checkable claim. The synthetic, personal-data-free `evidence-analyst-v1.0.4-request-versus-claim.json` fixture records one request-only negative case and two positive cases: a prediction inside a question and an actual reasoned choice followed by a question. They are semantic review expectations, not hard-coded phrase matching.

The Analyst session in this native route explicitly selects `claude-haiku-4.5`. One false positive cannot establish whether the model switch caused the error: the v1.0.3 prompt did not make the request-versus-claim boundary explicit, and there is no controlled before/after model comparison for this Episode. Focused deterministic eval validates the prompt version, fixture shape, and claim excerpts; **live native v1.0.4 semantic compliance remains pending**. A new native result and Core receipt are required before claiming the regression is fixed in operation.
