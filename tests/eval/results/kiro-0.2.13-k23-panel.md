# Mac 0.2.13 후보 패널 실측 (2026-10-18, K23)

격리 Kiro 프로필(`experiments/kiro-vsix-check-021`, Kiro IDE 1.2.56, 본선 계정, 모델 Auto, Autopilot)에 0.2.13 후보 빌드를 설치하고 실제 Kiro에서 확인했다. 빌드는 backend `3b16e19`와 program `972aef2`(마지막 후보 `k23d`)다. 학습자 발언은 모두 합성이며 실제 사용자 데이터가 아니다. 크레딧은 253.55에서 264.81이 됐다. 여기에 Discovery·Spec 2번, 채팅 4턴, Analyst 3번, Next Move 1번이 들어 있다.

## 흐름

1. 빈 폴더 `k23-ws`를 신뢰하지 않은 창에서 열었다. 목표는 "동아리 물품을 누가 빌려 갔는지 기록하는 간단한 API를 만들어 보고 싶어. 데이터베이스는 처음이야."이고, 첫 후보로 계획을 확정했다.
2. "이걸로 시작"을 누르자 바로 연결이 시작됐다. 카드는 다음 순서로 바뀌었다.

   | 단계 | 카드 |
   | --- | --- |
   | 연결 중 | "Kiro 채팅에 연결하고 있어요… 확인 창이 뜨면 골라 주세요." |
   | 연결됨, 신뢰 전 | "이 폴더를 신뢰하면 Kiro 채팅에 연결돼요."(host 알림 "신뢰 설정 열기"와 같은 시점) |
   | 신뢰한 뒤 | "창을 한 번 다시 로드하면 연결돼요." |
   | 다시 로드한 뒤 | 1초 안에 "오른쪽 Kiro 채팅에 이렇게 보내 보세요. 시작해 줘 [복사]" |

3. 복사 버튼을 누르자 클립보드에 `시작해 줘`가 들어갔다. 원래 클립보드는 되돌렸다.
4. 채팅에 "시작해 줘"를 보냈다. Builder는 뼈대를 만든 뒤 코드 전에 선택 두 개를 차례로 물었다.
   - 각 질문 때 카드는 "Kiro 채팅이 답을 기다려요."와 질문을 보였고, 진행 탭 배지는 1이었다.
   - 합성 답은 "2번으로 할게. 기록이 원본이니까 …", "1번이 좋겠어. 빌린 기록 하나에 반납일만 채우면 …"이다.
5. Task가 끝났다. 테스트 9개가 통과했고, 서버가 `localhost:3000`에 떠 있었다.
   - 카드는 "다 만들었어요. 결과를 확인해 보세요. 실행 방법과 열어 볼 주소는 Kiro 채팅의 완료 메시지에 있어요."를 보였다. 채팅 완료 메시지에 주소가 있었다.
   - 다음 한 걸음 3개가 2초 안에 떴다.
   - 2번 복사로 `다음 한 걸음 2번 해 보자`가 클립보드에 들어갔다.
6. 채팅에 "다음 한 걸음 2번 해 보자"를 보냈다.
   - Builder가 `check_progress`로 2번 "빌린 물품 기간 조회"를 확인하고 `save_progress`(PLAN)로 후속 Task를 시작했다. 후속 Task 완료 조건에 Next Move 2번이 들어갔다.
   - 그다음 날짜 범위 선택을 물었다.
   - 카드의 "이번 작업"은 `빌린 물품 기간 조회`로 보였다. "이렇게 진행돼요"는 접혀 있었다.
7. 학습 기록 탭은 열자마자 불러왔다. 지난 Project(K22)에서 남긴 원문 1개는 그 Project 이름과 "고른 이유"와 함께 보였다. 코드에만 쓰인 개념 11개는 "코드에 쓰인 개념" 이름 목록으로 모였다.

## 새 창 경로

- 물품 Project에 연결된 `k23-ws` 창에서 두 번째 Project(빵집 예약 주문)를 만들었다.
  - 확인 창에는 "지금 연 폴더는 다른 Project가 쓰고 있어요. Vibe Helper가 새 폴더를 만들어 새 창으로 열까요?"와 "새 창에서 ‘신뢰’를 누르면 패널이 다시 뜨기까지 보통 10~30초 걸려요."가 나왔다.
  - "새 창에서 열기"를 누르자 이 창 카드는 "새 창에서 이어서 만들어요."로 바뀌었다.
- 새 창 카드는 "신뢰"에서 시작했다. 신뢰를 누르면 "다시 로드"로, 다시 로드하면 4초 뒤 "시작해 줘 [복사]"로 바뀌었다. 채팅에는 새 세션이 열렸고 Autopilot이 켜져 있었다.

## 실측에서 찾아 고친 것

| 찾은 것 | 고친 커밋 |
| --- | --- |
| 다른 Project가 연결된 창에서 새 Project 카드가 "시작해 줘"를 권했다 | host가 hook의 Project id로 창을 구분한다(backend `3b16e19`, program `972aef2`) |
| 대기 중인 질문이 카드와 "이번 작업에서 고른 것"에 두 번 보였다 | 목록은 이미 고른 것만 보인다(program `6392509`) |
| 계획 화면에 `DATA_MODEL` 같은 분류 코드가 보였다 | 한국어 이름으로 바꿨다(program `6392509`) |
| 학습 기록이 개념마다 "코드에 쓰였어요 / 아직 내 말로 남긴 기록은 없어요"를 반복했다 | 코드에만 쓰인 개념은 이름 목록으로 모았다(program `c9ea35f`) |
| 다른 Project 원문의 출처가 없었다 | 출처 이름을 붙이되, 학습 목표 전체 문장인 이름은 단어 단위로 줄였다(program `99de9ec`, `4e25b6a`) |
| 후속 작업 이름이 "학습 목표 문장 + 후속 작업"이었다 | Next Move 이름이나 제품 이름으로 보인다(program `b9dfde1`) |
| 새 창 확인 창에 `WORKSPACE_FOLDER_IN_USE`가 보였다 | 쉬운 말로 바꿨다(backend `3b16e19`) |

## 오전 추가: 진행 메모와 펼침 표시 (program `65992d2`, `6ce8a0b`)

- **사용자 요청:** "지금 진행 중인 작업을 보여 줄 수 있으면 좋겠다", "메모 상자가 못생겼다", "누르면 동작하는 곳에는 힌트가 있어야 한다".
- **Core에 쌓이는 것:**
  - 학습자 메시지(UserPromptSubmit hook)와 턴 끝 요약(Stop hook)
  - 선택(질문·답·반영), Task 시작·완료, 개념 보고, Next Move
  - Live Context: Builder `save_progress` 때와 Core checkpoint(선택 대기, 테스트 시작, 완료) 때 버전이 쌓인다. 단계·목표·계획이 들어 있다. 첫 Task에서 7번이었다.
  - 턴 안의 파일 쓰기와 명령 하나하나는 hook이 없어 쌓이지 않는다.
- **표시:**
  - "만드는 중" 카드 아래쪽에 "Kiro 채팅의 최근 진행 메모"를 둔다. 남긴 시각, 단계 칩, 목표 3줄, 접힌 계획이 들어간다. Live Context가 이 Task의 것일 때만 보인다.
  - 메모가 실시간이 아니므로 "지금"이라고 쓰지 않는다.
- **실측(후속 Task, 답을 보낸 뒤 192초):**
  - 처음 66초는 밤에 남긴 PLAN 메모("후속 작업 계획, 오전 2:58")가 보였다.
  - 테스트를 시작하자 "테스트 실행, 오후 12:12"로 바뀌었고, 그 뒤 완료됐다.
  - Builder는 선택에 답을 받은 뒤 구현하는 동안 메모를 남기지 않는다. 더 촘촘히 보이려면 Steering에서 "답을 받고 구현을 시작할 때 save_progress"를 요구해야 한다. 아직 결정하지 않았다.
- **이 학습자 답은 인정됐다:** "이번 달에 몇 번 빌렸는지 세려는 건데, …두 번 세게 되잖아"는 `LIGHT_HINT`·`STRONG`이었고 직접 적용(DEMONSTRATED)으로 기록됐다. Builder 추천을 따라 말하지 않은 이유였다.
- **펼침 표시:** "이렇게 진행돼요", "이번 작업에서 고른 것" 항목, 메모의 "계획 N단계"에 오른쪽 화살표(열리면 뒤집힘), 마우스 반응, 손가락 커서, 키보드 초점 테두리를 넣었다. 탭에도 마우스 반응을 넣었다. 실제 Kiro에서 확인했다.
- **크레딧:** 이 후속 Task 턴 하나에 약 24가 들었다(264.81 → 289.05).

## 관찰만 한 것

- **Analyst 판정:** 합성 이유 두 개는 Builder의 추천 이유를 거의 따라 말해서 `DIRECTLY_LED`로 거절됐다. 정직성 규칙대로 동작한 것이며 패널 문제는 아니다.
- **승인 창:** 1개였다. `set -e`로 시작하는 여러 줄 `curl` 확인 스크립트(이 컴퓨터 주소만)가 미리 승인에 걸리지 않았다. 다음 Steering·미리 승인 정리 때 볼 것이다.
- **모델 출력:** 질문 문장 오타("컴럼", "훈어서")와 엉뚱한 낱말("courthouse") 한 번이 나왔다. `tool_call` 이스케이프 실패도 두 번 있었는데, Builder가 바로 평문으로 다시 보냈다.
- **지어낸 학습자 말:** 후속 Task 질문 뒤, Builder가 자기 답 안에 "user음, 근데 겹치는 걸 포함하면 …"이라는 학습자 말을 지어내고 거기에 답했다. Core에 남은 학습자 발언은 실제로 보낸 4개뿐이었다. 세 번째 선택도 답이 없는 상태로 남아 기록은 오염되지 않았다. 모델(Auto) 출력 문제로, 다시 나오면 Steering에서 다룬다.
- **업그레이드 직후 안내:** 같은 0.2.13에서 portable Core만 바뀐 빌드로 올리자, 첫 몇 초 동안 패널에 "이전 버전의 Core를 사용하는 Kiro 창이 종료되기를 기다리고 있어요"가 보였다. 이전 Core가 내려가자 스스로 사라졌다.
