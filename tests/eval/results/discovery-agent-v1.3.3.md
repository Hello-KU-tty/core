# Discovery prompt v1.3.3 product-first preview review

- Source: `PROJECT_BRIEF.md` §§1, 5, 7, 18 and canonical Discovery v1.3.2. The preview must already convey a project someone might finish and use; enrichment preserves its identity and cannot repair a technology-demo premise by silently replacing it.
- Observed baseline: one actual Kiro IDE native v1.3.2 Preview turn for a synthetic TypeScript memoization goal with no Personal Need produced ten diverse topics. The normalized-topic triage in `fixtures/prompt-regressions/discovery-v1.3.3-product-first-preview.json` is five weak, four conditional and one promising. It is not a full-field Candidate review or a quality score for v1.3.3. The F session also received an `EVIDENCE_AWARE` basis with an over-accepted earlier item, so it is not an isolated prompt A/B sample.
- Revision: preview generation now starts from a person's real task and completed result, then identifies a concrete place for the goal technology and a meaningful effect on behavior, correctness, responsiveness or change cost. The fallback Round rule and evaluation criterion use the same standard. Equivalent visible behavior alone no longer disqualifies feature-preserving technology such as caching. No cache, browser, calculator or title keyword gate was added to the canonical prompt.
- Evaluation fixture: retains the ten observed themes at topic granularity, a useful feature-preserving counterexample, a technology-demo counterexample, four human review criteria and two generalization inputs with and without Personal Need. The revised native result remains `PENDING`; full saved preview fields and Core receipt are needed before a human can score its product quality.
- Automated verification on Node.js 24.19.0 and pnpm 11.12.0: `pnpm test:eval` passed 29/29 and `pnpm build` passed after all Discovery version constants were synchronized to 1.3.3. These checks validate prompt assembly and fixture integrity, not the model's semantic improvement.
- Next live review: use the same synthetic goal and no Personal Need, preserve the existing F lineage, record the personalization basis separately, and assess each saved preview's user task, result, technology implementation effect, first-MVP burden and diversity. Run at least one different unseen goal and one Personal Need case before claiming the generic rule transfers. Kiro IDE/CUA execution is owned by the parent experiment.
