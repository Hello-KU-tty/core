# Evidence Analyst v1.0.5: application and prior-Agent dependence

In the isolated Kiro IDE run for synthetic project G, the second Helper exchange said it was based on the preceding explanation, predicted two outcomes, and proposed how to copy a changed object. The native Analyst submitted three `STRONG / LIGHT_HINT` proposals from that one USER message. Core accepted all three: two `PREDICTION` proposals supported `EXPLAINED`, and an `APPLICATION` proposal supported `DEMONSTRATED`.

All three `concept.originalExpression` and `redactedEvidenceExcerpt` fields were exact substrings of the cited USER event. That proves quote provenance, not that the claims were independent of the preceding Helper answer. The Analyst's own uncertainty said the prior Agent might have supplied the answer. That prior Helper response was in a different conversation and Episode, whereas `ANALYST_GET_EPISODE_CONTEXT` returned only the current Episode's two Events. The `APPLICATION` proposal also described an anticipated remedy that the user asked the Helper to check; it did not cite a committed project choice, instruction to adopt the remedy, performed correction, or verified result. The `DEMONSTRATED` state was therefore overstated. The two `EXPLAINED` proposals remain semantically uncertain because the prior-answer dependence could not be checked. Existing accepted rows and Concept State were preserved, not rewritten.

Prompt v1.0.5 asks the Analyst to separate a proposed or predicted solution from an actual project decision or application. It allows `DEMONSTRATED` for a user-authored, reasoned choice even before code is written. When the user explicitly builds on an earlier Agent explanation that is absent from the supplied Episode, the Analyst must withhold state support rather than infer `LIGHT_HINT` or independence from the user's level of detail. A visible near-repeat is directly led; a separable new, attributable decision can still be evaluated. The same-Task Transfer rule now uses the same application boundary. The Core's exact-quote gate and deterministic state policy are unchanged.

The synthetic, personal-data-free `evidence-analyst-v1.0.5-application-dependence.json` fixture records two negative cases (unavailable prior answer and visible direct repetition), a tentative prediction limited to `EXPLAINED`, and a positive reasoned project choice after an Agent supplied only a decision criterion. Focused tests verify prompt/version wiring and fixture expectations; they do not prove native model compliance. A new live Analyst turn is needed to measure that behavior. Supplying bounded prior Agent context to the Analyst is a separate provenance improvement, not part of this prompt change.
