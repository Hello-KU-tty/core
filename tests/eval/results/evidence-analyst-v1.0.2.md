# Evidence Analyst v1.0.2 boundary regression

Canonical prompt `docs/agent-prompts/evidence-analyst.md` v1.0.2 clarifies two existing Core constraints: `concept.originalExpression` is a faithful user phrase of at most 120 characters, with a separate redacted evidence excerpt; `userEvidenceSources` contains only the strict kind-specific reference keys from an input Event's `sourceReferences`.

The synthetic, personal-data-free fixture `tests/eval/fixtures/prompt-regressions/evidence-analyst-v1.0.2-bounds.json` uses a user question longer than 120 characters. A short concept phrase plus an exact USER_MESSAGE reference passes `analystSemanticResultSchema`; putting the whole question in `originalExpression` and adding an excerpt key to the reference fails. This is a deterministic contract boundary check, **not** an Agent output or a live model success. The existing v1.0.1 mixed-strength fixture remains unchanged and still checks directly led versus independent Evidence.

Before this clarification, the same persistent native Helper Episode returned JSON twice on one manual retry: both attempts exceeded the `originalExpression` limit, and one also added unsupported reference keys. Both were rejected as `ANALYST_INVALID_RESULT`; no Evidence was accepted. On a later live retry under v1.0.2, its native output passed the strict JSON schema on attempt 1, but Core rejected both Proposals as `INVALID_REFERENCE` because their direct USER source references were not found in that Episode. Prompt/schema compliance improved; semantic provenance was still incorrect for this Episode. On one further retry of the Decision-with-rationale Episode under v1.0.2, native output passed and Core accepted two of three Proposals, advancing two Concept Ledgers to EXPLAINED revision 1; the third was conservatively rejected as `INSUFFICIENT_EVIDENCE`. These UI inputs were synthetic product-channel tests, not real learner proof. The 30-second Analyst timeout and deterministic Core policy are unchanged.

Validation: targeted eval and Analyst adapter tests 29/29, TypeScript typecheck, build, format check. Live outcomes are documented in `docs/spikes/T19_NATIVE_LIVE_RUN_20260913.md`; they do not establish flawless Analyst reliability or full-flow completion.
