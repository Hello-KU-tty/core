# Mac 0.2.13 후보 결정 순간 Helper 안내 실측 (2026-10-18, K24)

격리 Kiro 프로필(`experiments/kiro-vsix-check-021`, Kiro IDE 1.2.56, 본선 계정, 모델 Auto, Autopilot)에 0.2.13 후보 `k24a`(backend `c32979d`, program `d314006`, Steering 0.9.6)를 설치하고 실제 Kiro에서 확인했다. 학습자 발언은 모두 합성이며 실제 사용자 데이터가 아니다.

## 흐름

1. 빈 폴더 `k24-ws`에서 처음 보는 목표 "스터디 모임 출석을 기록하고 누가 몇 번 빠졌는지 볼 수 있는 웹 서비스를 만들어 보고 싶어. 서버 API랑 데이터베이스는 처음이야."로 Discovery를 돌렸다(Personal Need 없음). 첫 후보 "출석 현황판"으로 계획을 확정했다. 예상 Decision은 두 개(회원 식별, 출석 API 입력)였다.
2. 같은 창에서 연결하고 다시 로드한 뒤 폴더의 Steering이 0.9.6인지 확인했다(`vibe-helper-learner.md`, `vibe-helper.md`).
3. "시작해 줘"를 보냈다. Builder는 환경 확인, 계획 메모, 뼈대를 만든 뒤 테이블을 만들기 직전에 첫 선택을 기록하고 물었다(2.32크레딧). 이 Mac의 Node 26에서 `better-sqlite3` 빌드가 실패해 `node:sqlite`로 바꾸고 `ERROR_REPLAN` 메모를 남겼다.
4. 첫 선택 메시지(선택지 두 개 다음, 마지막 질문 앞):

   > 답을 지금 몰라도 괜찮아요. 고르기 전에 저한테 먼저 물어봐도 돼요. 예를 들어 `/vibe-helper 1번이랑 2번이 "같은 이름이 두 명일 때" 어떻게 다른지 설명해 줘` 처럼요. 이건 예시일 뿐이고, 궁금한 점이나 헷갈리는 부분을 그냥 본인 말로 물어보는 게 제일 좋아요.

   메시지는 추천과 "어느 쪽이 좋을지, 그리고 왜 그렇게 생각하는지 본인 말로 들려주세요."로 끝났다.
5. 패널 "지금 할 일"은 "Kiro 채팅이 답을 기다려요.", 질문, "잘 몰라도 괜찮아요. 고르기 전에 먼저 물어보세요.", "예를 들면 이렇게요", 예시 줄과 "예시 복사", 예시 안내, 번호와 이유 안내를 보였다. "예시 복사"를 누르자 클립보드에 `/vibe-helper 이 선택지들이 뭐가 다른지 쉽게 알려줘`가 들어갔다(원래 클립보드는 되돌렸다).
6. 복사한 문구를 그대로 채팅 입력칸에 넣어 보냈다(메뉴에서 고르지 않음).
   - Kiro가 이 턴에 `vibe-helper.md` Steering을 붙였다(세션 기록 `steering_inclusion`). 글자로 넣은 `/vibe-helper`도 Helper 모드가 된다.
   - 도구 호출 0번(파일 수정·명령·기록 도구 없음). 두 선택지를 출석 장부 비유로 비교했다.
   - "마음이 정해지면 번호와 그 이유를 본인 말로 들려주세요. (지금 고르지 않아도 괜찮아요.)"로 끝났다(0.22크레딧).
7. 합성 답 "1번으로 할게. 이름에 오타가 나면 다른 사람으로 세어진다는 게 걸려서, 번호로 묶어 두는 게 나을 것 같아."를 보냈다. Builder가 `save_choice` 1과 `DIRECTION_CHANGE` 메모를 남기고 DB 계층을 쓴 뒤, 라우트 직전에 두 번째 선택을 물었다(1.23크레딧).
8. 두 번째 선택 메시지에도 안내가 다시 나왔고, 예시는 그 선택에 맞게 새로 썼다:

   > 이것도 지금 당장 답을 몰라도 돼요. 고르기 전에 저한테 물어봐도 괜찮아요. 예를 들어 `/vibe-helper 2번에서 없는 회원 ID로 출석하면 서버가 어떻게 반응해?` 처럼요. 예시일 뿐이니, 헷갈리는 부분을 본인 말로 편하게 물어보는 게 제일 좋아요.

9. Core 기록(SQLite 사본): 첫 선택의 연결 발언은 "시작해 줘"(Builder 탭, 질문 전), `/vibe-helper` 질문(Helper 탭, 질문 후), 답(Builder 탭, 질문 후)이다. 이벤트 순서는 `DECISION_REQUESTED` → `USER_MESSAGE` → `HELPER_RESPONSE` → `USER_MESSAGE` → `DECISION_RESOLVED`다.

두 번째 선택은 답하지 않은 채로 두었다.

## 크레딧

## 남은 것

- Builder가 "저한테 물어봐도 돼요"라고 말한다. `/vibe-helper` 턴도 같은 채팅이라 틀린 말은 아니다. Helper라는 이름을 꼭 써야 하는지는 사용자 판단으로 남긴다.
- 메뉴에서 고른 `/vibe-helper`는 이번에 다시 보지 않았다(K10·K17에서 확인).
